# 2. Vendor GitHub's gemoji data for emoji shortcodes

- **Status:** accepted
- **Date:** 2026-10-27

## Context

Issue #2 asks for emoji shortcodes (`:tada:` → 🎉). Fidelity to GitHub is the project's
reference, so the set of names matters: GitHub resolves shortcodes with its own database,
[gemoji](https://github.com/github/gemoji) (MIT), whose names differ in places from other
lists (`:+1:`, `:thumbsup:`, `:shipit:`…). markdown-it-py has no emoji plugin of its own.

Options considered:

- **The `emoji` package from PyPI** — maintained, but a new runtime dependency (~200 KB) whose
  alias list follows Unicode CLDR names plus its own aliases, not GitHub's. Some GitHub
  shortcodes would be missing or map to different emoji.
- **`mdit-py-emoji` or similar plugins** — small community packages with uncertain
  maintenance, again with their own name lists.
- **Vendor gemoji's data** — generate a compact `alias → emoji` JSON from gemoji's
  `db/emoji.json` at a pinned commit, ship it as package data (~46 KB) and write a small
  markdown-it rule. Exactly GitHub's names; no runtime dependency.

## Decision

Vendor gemoji's data in `src/md2html/assets/emoji.json`, generated by
`scripts/update_emoji.py` from a pinned gemoji commit recorded in the file, together with
gemoji's license notice. Conversion is a markdown-it core rule in `src/md2html/emoji.py`
that follows GitHub's rules as observed through GitHub's Markdown API (see the module
docstring and `tests/test_emoji.py`).

## Consequences

- Shortcode names match GitHub's, and the package keeps having no extra runtime dependency.
- New emoji require running `scripts/update_emoji.py <commit>` and committing the regenerated
  file; the diff is one line per shortcode, so updates are easy to review.
- GitHub's custom image emoji (`:octocat:`, `:shipit:` images) are not in gemoji's character
  data and stay as text, which also keeps the page free of remote images.
- GitHub's tokenizer has rare context-dependent behavior (e.g. after `a:x:b`, a following
  `:smile:` is not converted on GitHub); md2html applies its documented rule consistently.
